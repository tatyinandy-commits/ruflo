# Как наполнять `best`

Этот проект мы ведём вместе. Чтобы он оставался полезным, а не свалкой — несколько правил.

## Чек-лист для нового элемента

- [ ] Лежит в правильной папке (`skills/`, `agents/`, `commands/`, `hooks/`, `mcp/`, `prompts/`, `scripts/`).
- [ ] Имеет понятное имя в `kebab-case`.
- [ ] Содержит назначение (зачем) и пример использования (как).
- [ ] Самодостаточен — работает после копирования в чужой проект.
- [ ] Добавлен в [`catalog.json`](./catalog.json).

## Быстрый старт

```bash
best/scripts/new-item.sh <type> <name>
# type: skill | agent | command | prompt
```

Скрипт создаёт файл из шаблона с правильным frontmatter. После — заполни содержимое
и допиши запись в `catalog.json`.

## Форматы

### Skill (`skills/<name>/SKILL.md`)
```markdown
---
name: my-skill
description: Кратко, что делает скилл и когда его применять.
---

# Заголовок

## Overview
...
```

### Agent (`agents/<name>.md`)
```markdown
---
name: my-agent
description: Чем занимается агент.
---

You are ...
```

### Prompt (`prompts/<name>.md`)
Свободный markdown: контекст, сам промпт в блоке, заметки по использованию.

## Что НЕ добавляем

- Секреты, токены, `.env` — никогда.
- Дубли того, что уже есть в `.claude/` основного репо без причины.
- Незаконченные черновики без описания.
